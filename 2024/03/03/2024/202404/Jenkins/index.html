CI/DI简介

CI/DI就是持续集成与部署，持续集成（Continuous integration），持续部署（Continuous deployment）。

持续集成：频繁地将代码集成到主干。通俗的来说就是将不同分支的代码提交到代码仓库，如GitLab。将非主分支合并到主分支上。并进行构建测试，确认是否正确的集成。

持续部署：将集成测试完成的项目部署到对应的环境。

首先，开发将代码提交到代码仓库，将代码的改动合并到相应的分支。

下一步，Jenkins利用git、maven等插件，对提交的代码进行拉取、测试、打包等，

最后，将代码打包成jar/war推送到测试、生产服务器进行部署。

凭证管理

我们需要jenkins从git上拉取我们提交的代码，git肯定是需要访问凭证信息的，此时我们可以创建一个连接git的凭证，在拉取项目代码时可以使用。

安装 Credentials Binding 插件，我这里已经安装了，跳过。安装完之后，会有一个凭证管理入口

点击进去之后，添加凭证

有五种凭证类型

  1. Username with password ：用户名和密码方式
  2. SSH Username with private key： 使用 SSH 用户和密钥
  3. Secret file： 需要保密的文本文件，使用时 Jenkins 会将文件复制到一个临时目录中，再将文件路径设置到一个变量中，等构建结束后，所复制的 Secret file 就会被删除
  4. Secret text： 保存一个加密文本，如GitHub 的 api token
  5. Certificate： 通过证书方式

流水线

概念

将原先一个任务做完的事情，拆分为多个子任务执行，以流水线的方式执行。

由于拆分为多个子任务，可以观察每个子任务执行的状态，并在出现问题的时候，可以迅速查询出问题点，提高效率。

功能特性

两种实现方式

脚本式pipeline

基于groovy的DSL语言实现，提供了大量的灵活性和可拓展性。因为jenkins的基于java实现的，所以很早引入了groovy作为DSL。如果使用groovy来编写jenkins file，这对与小白是有难度的，所以就有了声明式pipeline出现。

声明式pipeline

适合没有编程经验的初学者，并得到了官方越来越多的支持。

实践

创建流水线项目，如果没有改选择，则需要下载Pipeline的插件

两种定义方式

Pipeline Script：直接把脚本内容写到脚本对话框中
Pipeline script from SCM ：Source Control Management–源代码控制管理，即从gitlab/github/git上获得pipeline脚本–JenkisFile

刚开始不会写脚本咋办呢，可以使用 Pipeline Syntax 来生成。

触发器

我们配置项目的时候，会有如下图所示的选项

Build whenever a SNAPSHOT dependency is built：

当job依赖的快照版本被build时，执行本job。

**Trigger builds remotely (e.g., from scripts)**：

触发远程构建。

Build after other projects are built：

当本job依赖的其它job被build时，执行本job。

Build periodically：

定期构建，就是设置定时器每隔一段时间进行自动构建、部署。

Poll SCM：

指定特定时间，比较一次源代码是否发生变更，若发生则Build。

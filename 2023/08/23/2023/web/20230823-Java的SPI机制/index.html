  1. 什么是SPI

    全称 Service Provider Interface

    Java SPI机制是一种基于接口的服务发现机制，它允许应用程序在运行时发现并加载实现特定接口的服务提供者。它是Java编程语言的一种规范。通过SPI机制，应用程序可以通过配置文件的方式，动态地加载实现了某个接口的类，并使用这些类提供的功能，而无需在代码中显式引用它们，这样就可以让应用程序具有更高的灵活性和可扩展性。

    通俗一点就是将服务方与调用方通过接口进行隔离，调用方不用关心服务方是如何实现的，并且服务方内部改变逻辑，调用方也无需变动，对于调用方来说是无感知的。

    SPI可以理解为是调用方提出来一个规范，接口定义在调用方，服务方需要根据这个规范去实现。例如官方声明一个连接Mysql数据库的 Driver接口规范，那么服务方需要根据这些规范去实现，调用方只需要通过特定的方式（META-INF/services/）去加载并使用**Driver **接口的实现类即可。跟Java的接口很类似，只不过接口的定义和实现都在服务方，调用方只需要调动服务方提供的接口即可。

  4. DriverManager

    我们首先看一下DriverManager类的源码描述，

    JDBC 4.0 Drivers must include the file META-INF/services/java.sql.Driver. This file contains the name of the JDBC drivers implementation of java.sql.Driver

    JDBC4.0开始需要包含META-INF/services/java.sql.Driver 文件，并且包含的JDBC驱动器实现 java.sql.Driver。这只是MYSQL驱动器的一个例子。

    之前连接数据库的方式，相信大家很熟悉吧，当初大学刚开始学习数据库的时候，就是这样写的。

    高版本JDBC连接数据库的方式，这里直接省略了 **Class.forName(“com.mysql.jdbc.Driver”)**代码，因为源码里面已经帮我们干了这件事。

    看一下DriverManager类源码，以Mysql驱动器为例。

    通过静态方法使用ServiceLoader去加载Driver接口的相关想实现，在通过迭代器的next方法加载对应的驱动类。并且Mysql驱动类通过静态方法注册自己的驱动器实现类，注意迭代器加载类时，会执行Mysql驱动类的静态方法，也就是会把自己的实现类注册到DriverManager的registeredDrivers中。
